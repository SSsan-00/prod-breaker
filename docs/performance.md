# v2.22.3 パフォーマンス検証

2026-10-29。比較元は v2.22.2 (`d80f6ce3cdc00f13ef09fc99a7d67fd8585b0129`)。
Node.js 24.19.0 / Linux、ブラウザ確認は Playwright Chromium。

## 変更内容

- 固定ステップごとの `structuredClone` を、ゲーム状態の構造に合わせたコピーへ変更。入力状態を変更せず、電撃の終点と移動する敵・プレイヤーの参照関係も保持。
- 連鎖キューの先頭削除と対象の再検索を省略。発射対象の距離計算をまとめ、復旧BOTの最寄り対象を1回の走査で取得。
- 弾の円形当たり判定の前に矩形で候補を絞り込み。最終的な距離計算・境界条件・処理順序は維持。
- Canvasのサイズを `ResizeObserver` で保持し、毎フレームのレイアウト情報取得を除去。
- サーバーの位置・構成が変わるまで接続線の `Path2D` を再利用。
- ゲーム状態・スティック・画面サイズが変わらない描画を省略。スティック初回表示でレーダー枠の線幅が変わる既存の挙動も保持。

## 判定処理の計測

同一環境で変更前後を交互に計測。各実装500回のウォームアップ後、1,000回の更新を7セット計測した中央値。値は1更新あたりの処理時間で、FPSやスマホ実機の性能を表すものではありません。

| 条件 | 変更前 | 変更後 | 処理時間削減 |
| --- | ---: | ---: | ---: |
| 開始直後の状態 | 0.0396 ms | 0.0121 ms | 69.6% |
| 高負荷の合成状態 | 1.0740 ms | 0.4463 ms | 58.4% |

高負荷条件は敵・サーバー100、弾120、ログ160、演出100。実プレイの全場面を代表する数値ではなく、端末や状況によって効果は異なります。

## 描画回数の計測

スマホ相当のブラウザでシード13、同じ時計・操作条件を使用。起動時のサイズ取得は観測区間に含みません。

| 観測区間 | 変更前の描画 / サイズ取得 | 変更後の描画 / サイズ取得 |
| --- | ---: | ---: |
| プレイ中500 ms | 32 / 32回 | 15 / 0回 |
| 強化選択中1,000 ms | 63 / 63回 | 0 / 0回 |

ゲーム判定は従来どおり毎秒30回。描画間の補間は従来からなく、同じ状態を重ねて描く処理を省いています。

## 挙動と画面の比較

- 90秒・3分・5分・30分の固定入力シミュレーションで **69,837回の全状態が完全一致**。得点、乱数状態、敵、弾、演出、強化選択を比較。30分の比較のみ、全60WAVEを検証するためプレイヤーを無敵に設定。
- 入力状態の不変性、電撃終点の参照関係、円形当たり判定の境界を単体テストに追加。
- 320×480 / 393×851 / 851×393 / 1280×720、演出軽減ON/OFF、7つの連続場面の **56スナップショットが一致**。PANIC、ダメージ、SRE CORE、ネットワーク構成変更、カメラ移動、同一ゲーム状態でのスティック開始・移動・解除を比較。
- 上記画像比較はCanvasの完全に描画される画素領域を対象とし、小数DPRによる最下端の部分画素は除外。Reactの代わりに最小限のフックを与え、実際の描画コードをブラウザで実行。
- 本番ビルドのE2Eで、PC/スマホ操作、一時停止中の再描画抑制、リサイズ・再開、進化、90秒通しプレイ、リザルト、名前変更、ランキングを検証。
- lint、型検査、単体テスト47件、本番ビルド成功。E2Eは25件成功、対象端末が異なる9件を意図的にスキップ。

## 再実行

比較元のGitコミット、Node.js 24、インストール済みChromiumが必要です。計測値を固定閾値のテストにはせず、状態・画面の不一致のみ失敗とします。

```sh
node scripts/performance.mjs --baseline d80f6ce
node scripts/render-performance.mjs --baseline d80f6ce
```

iOS Safariやスマホ実機の処理時間・消費電力は未計測です。
